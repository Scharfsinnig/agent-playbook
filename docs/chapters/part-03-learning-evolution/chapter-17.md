# 第 17 章　无人工标注学习、内在动机、自博弈、技能发现与世界模型：探索不等于可上线能力

## 17.1 先拆开几个常被混用的词

“无监督 RL”没有覆盖所有论文与工程实践的唯一严格用法，较准确的核心是：在没有人工任务标签或外在任务奖励的预训练/技能发现阶段，策略仍按某个内在目标探索，例如新颖性、预测误差、互信息或状态覆盖。它显然仍有目标函数、采样偏好和奖励信号。DIAYN 的方法通过让技能与访问状态可区分来最大化互信息，得到多样化行为；多样化不自动等于对企业任务有用、安全或可组合。[Eysenbach et al., DIAYN](https://openreview.net/forum?id=SJx63jRqFm)

“没有人工标注”范围更宽。程序 verifier 的 RLVR、模型反馈的 RLAIF、胜负奖励的自博弈、从日志获取的业务回报，都可能减少人工标签，但各自仍有外部目标或奖励。Constitutional AI 以人写原则和 AI 反馈减少人工标注某些有害输出的需求，其 RL 阶段仍用偏好模型作为 reward signal。[Bai et al., Constitutional AI](https://arxiv.org/abs/2212.08073) “没有 SFT 冷启动”也不等于无监督：模型仍可能依赖预训练基座、格式约束、验证奖励和大量 RL 采样。产业文档应避免把这些不同信号混称为“模型自己学会”。

## 17.2 内在奖励与好奇心：奖励探索可达性，不奖励随机噪声

内在动机的目标是当外在奖励稀疏时，促使策略发现更多可学习状态。预测误差、新颖性、信息增益或学习进展都可作为内在奖励。ICM 以自监督的特征预测误差激励探索，但随机、不可控的环境也会持续产生高预测误差，形成所谓“白噪声吸引”。[Pathak et al., ICM](https://proceedings.mlr.press/v70/pathak17a.html) 因此工程上应关注 episodic novelty、可控性、学习进展而非单纯不可预测性，并对访问次数、工具成本和高风险环境设预算。

采购 Agent 不适合仅因“发现了陌生合同格式”就自由尝试写操作。内在奖励在企业环境中更合理的用途是离线 sandbox 中探索工具覆盖、发现未知错误码、生成测试案例或提高状态空间覆盖；它必须被外部任务验收和硬策略约束包围。衡量指标应是覆盖到的有效状态、下游迁移、发现的真实缺口、噪声访问率和资源成本，而非内在 reward 本身。没有外部 gate 的新颖性优化不应改变真实系统。

## 17.3 自博弈、自动课程与技能库：需要外部锚点

自博弈让策略与自身或历史策略对抗，胜负形成训练信号；league 则保存多代对手以降低循环策略和遗忘。它适合有明确对抗结构、可模拟环境或可验证题目生成的场景。自动课程通过能力诊断安排从短程、高信噪任务到更难任务，以改善探索和信用分配。Voyager 在 Minecraft 中结合自动课程、代码技能库和环境反馈，展示了开放环境中积累程序性技能的可能性。[Wang et al., Voyager](https://arxiv.org/abs/2305.16291)

但企业 Agent 的任务通常不是对称博弈。采购变更的“对手”若由同一模型生成合同冲突、再由同一模型评判，就会把生成器偏好误当作能力。自博弈用于此类任务时，应将其限制为训练数据扩增或 sandbox 压力测试：保留历史策略池、使用外部规则/隐藏 verifier、对旧版本和外部基准进行评测，并监控策略多样性、外部成功与漏洞利用率。内部 Elo 上升而隐藏合同集成功不升，说明系统在自洽但无用的循环里优化。

技能库也应被视为可执行制品，而不是模型记忆。每个技能需有输入/输出契约、所需权限、适用域、依赖、测试、来源和撤销开关。自动发现的“发送通知”技能在 sandbox 可以执行；进入生产前应被分解为草拟、审批、发送和写后核验等受控动作。课程的难度不能只按 token 长度或模型自评排序，而应按可验证成功率、风险、覆盖和迁移表现调整，并混入旧任务防止只会通过新课程。

## 17.4 世界模型：预测环境，不等于拥有世界知识

世界模型在 RL 中通常近似环境的状态转移，常同时预测观测和奖励，使策略能在模型内部 rollout、比较行动后果并减少真实交互。Dreamer 系列是通过潜空间动态模型进行想象训练的代表工作。[Hafner et al., DreamerV3](https://arxiv.org/abs/2301.04104) 它与“语言模型学习了很多世界知识”不同：前者要求对特定环境转移有可校准的预测能力，并以规划收益与模型误差来评价。

对采购 Agent，可以建立受限的流程世界模型或数字孪生：合同状态如何随草稿、审批、提交、撤销而转移；哪些工具错误可恢复；审批队列的延迟分布；不同动作的成本和风险。其用途是离线测试计划、生成反事实场景、选择低风险探索或训练 verifier，而不是替代 ERP 的真实读写。必须报告一步预测误差、多步 rollout 误差、不确定性校准、模拟—真实差距和在真实回执上的规划收益。模型在分布外条款或新工具版本上自信地预测成功，正是最危险的情形；不确定性高时应回到真实验证、人工审批或只读路径。

世界模型的训练数据同样需要版本化环境语义。若 ERP 把“草稿已保存”的状态码改为“待校验”，旧转移模型可能仍给出过时 rollout；若审批规则随地区变化，单一全局转移概率会掩盖风险差异。部署时应把世界模型视为建议或测试资产，并把其预测与真实观察的残差持续记录。残差显著上升、关键状态未覆盖或不确定性校准失效时，自动规划应降级为规则路径或人工确认，而不是继续基于错误模拟扩展探索。

## 17.5 产业采用的判定标准

无人工标注机制进入生产前至少要回答：外部可验证目标是什么；谁控制奖励、题目、judge 和发布；策略能否接触或篡改这些面；下游验收与内在/自博弈指标是否相关；未知分布、噪声和对抗输入上如何停止或交接。任何能改变真实系统的策略都不应仅凭自我评价、新颖性、内部 Elo 或合成数据分数发布。更准确的产业路线往往是“低人工标注的内在/自监督预训练或 sandbox 探索，加上独立 verifier、真实业务门禁和人工责任的下游适配”，而不是追求没有监督的自动进化。
