# 第一篇：站在 Agent 的视角，看一次任务怎样真正完成

第一篇暂时不讨论应该选择哪家模型，也不从框架名称开始。我们先跟随一个 Agent 从请求进入系统的那一刻向前走：它怎样把模糊语言变成任务契约，怎样区分业务真相、执行状态、上下文和记忆，怎样形成计划并选择下一动作，工具结果回来后怎样验证，失败时怎样重试、回滚或求助，最终又凭什么停止。只有把这条链理解清楚，后续的模型、微调和持续学习才有明确落点。

贯穿本篇的例子是“供应商准入调研 Agent”。采购负责人要求系统在两天内为候选供应商形成有证据的准入意见，需要读取合同、内部政策、公开风险信息和工单；发现制裁、数据跨境或合同例外时必须交给对应负责人。这个 Agent 可以读取已授权系统并生成内部草稿，但不能修改供应商主数据、签署合同或向外部发送邮件。它同时包含开放式检索、稳定业务规则、敏感信息、异步等待和多角色会审，适合用来暴露 Agent 的真实工程问题。
