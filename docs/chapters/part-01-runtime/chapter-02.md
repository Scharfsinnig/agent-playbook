# 第 2 章　请求进入系统后：如何建立任务契约与完成定义

## 2.1 自然语言请求为什么不足以启动真实行动

采购负责人说“帮我评估供应商 A 是否能准入”，其中至少含有五类未定信息：评估的业务目的是什么，A 指向哪个实体，允许读取哪些材料，何时必须给出结果，以及“能准入”究竟由谁定义。若这些问题不在任务开始前转为结构化契约，模型会以训练语料中的常识补空；它可能把一般信息搜索误当成合规审查，把旧合同当成现行合同，或在找不到信息时编造结论。生产系统必须把澄清也当作一种合法动作，而不是错误。

任务契约（task contract）是运行时可读取、可版本化的任务边界。它至少描述目的、委托主体、资源范围、允许和禁止动作、数据分类、验收谓词、要求保留的证据、预算、截止时间、风险门和合法终态。契约不是把一段自然语言系统提示换成 YAML；它应被策略引擎、工具网关、状态机和验证器共同消费。模型看到的是经过编译的、与本轮决策有关的投影；权限与完成定义仍在模型外强制。

在案例中，系统可将请求编译为如下对象。字段的具体格式可以不同，关键是它能由确定性组件验证：

```yaml
task_contract:
  purpose: "形成供应商 A 的准入调研意见，不产生外部写入"
  principal: "procurement:requester-17"
  scope:
    supplier_id: "supplier-a-uuid"
    allowed_resources: ["contract:tenant-x", "policy:tenant-x", "public-risk"]
    allowed_actions: ["read", "retrieve", "draft", "request_approval"]
    forbidden_actions: ["update_supplier", "send_external_mail", "sign_contract"]
  success_predicates:
    - "每项结论均有有效来源与版本"
    - "制裁、数据跨境、合同例外三类检查均有验证结果"
    - "结论与风险例外被明确区分"
  evidence_required: ["source_refs", "policy_versions", "tool_receipts"]
  budgets: {deadline: "2026-08-20T10:00:00+08:00", tool_calls: 60}
  terminal_states: ["succeeded", "blocked", "handoff", "failed", "canceled"]
```

## 2.2 完成是谓词，不是措辞

任务契约最容易被偷换的部分是完成定义。模型输出“该供应商风险可接受”不是完成；即使文档看起来专业，也不能证明它核对了正确对象和正确版本。完成必须写成能够由外部状态、测试、回执或指定人工签字检查的谓词。例如“制裁筛查工具在本次 run 中返回有效结果”“合同条款版本与审批系统当前版本一致”“每个实质性结论能追溯到经授权的证据项”。对于开放式研究，无法要求唯一正确答案，但仍可要求证据覆盖、冲突披露、交付格式和用户验收。

失败、阻塞和等待同样要在契约中合法化。制裁筛查服务不可用时，Agent 不应为了达到 `succeeded` 而用旧缓存冒充结果；它应进入 `WAIT` 或 `BLOCKED`，交付已完成部分、缺失的证据及下一步所需权限。把这些终态预先列出，能够避免团队在指标上只奖励“完成”，从而诱发系统掩盖不确定性。

## 2.3 风险先于规划

规划之前需要做风险分级，因为风险决定允许的动作空间。读取公开网页与导出含个人信息的合同附件不是同一类操作；给出内部草稿与向外部供应商发送邮件也不是同一类操作。一个实用的自治信封由可验证性、可逆性、最小权限和接管能力共同决定：任何一项很弱，都应缩小自治范围。这里不应把“整个 Agent”贴成高或低风险，而要对动作分级。读取合同可在策略范围内自动执行，更新供应商主数据可能需要逐次审批，签署合同则通常保留给人。

审批本身也需要契约化。批准人批准的应是某一次 run 中、某个对象、某组参数哈希和某段有效期内的动作，而不是模糊地批准“让 Agent 继续”。系统应把审批绑定到 `run_id`、`action_id`、影响摘要、撤销窗口和策略版本。审批人在等待期间，目标资源、权限或价格可能变化；执行前还要重新验证关键前置条件，不能把早先的同意无限期复用。

## 2.4 契约建立的实际步骤与指标

运行时可用四步完成建约。第一步解析请求，抽取候选主体、目标和动作；第二步对缺失的高后果槽位发起澄清，而不是猜测；第三步由确定性规则补入组织政策、数据域和默认预算；第四步冻结一个契约版本，记录是谁确认、何时生效、哪些字段可在后续通过显式变更事件修改。若用户把“仅内部调研”改成“向供应商索取材料”，这不是普通对话补充，而是一个改变权限和副作用的契约修订。

需要监测的不是契约文本的长度，而是契约缺失率、因范围不清导致的人工交接率、模型提案被策略拒绝的原因分布、验收谓词被验证器拒绝的比例，以及契约修订后发生的错误副作用。大量“模型能力不足”的投诉往往会在这些指标中显示为对象解析、权限边界或验收标准缺失。

契约不能取代法律意见或组织责任。地区、行业、服务对象和数据类型可能改变披露、记录、保留与人工复核的要求；系统应保留适用性结论和证据映射，由法务与隐私负责人维护，而不能根据“使用了 Agent”自动得出合规结论。契约的作用是把这些外部结论落实为可执行的范围与门，而不是发明法律规则。
