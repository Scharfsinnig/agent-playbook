# 第 7 章　验证、纠错和停止：如何避免幻觉、漂移与无限循环

## 7.1 验证不等于让模型再回答一次

执行模型最容易验证自己刚刚生成的结论，因为它能复述同一条叙事；这恰恰使错误相关。有效验证要根据主张类型选择独立的检查面。供应商报告中的合同版本可由数据库版本号验证；制裁筛查可由权威工具回执和时间戳验证；引用是否支持某句话可由 claim-to-evidence 检查和人工抽样验证；写入是否生效则需要 read-after-write 或最终一致窗口后的状态观察。模型 Judge 可以用于开放式质量和覆盖度，但应在人标保留集上校准，并且不能作为安全放行的唯一机制。

因此一次动作要区分三层 verdict。`execution receipt` 表明调用在协议层的结果；`state observation` 表明外部对象被观察到的状态；`goal verification` 表明这些状态满足任务契约。把三者分开可以解释为什么“HTTP 200”之后仍需重规划，也可防止模型把工具文本中的“success”误当作业务完成。

## 7.2 纠错是状态转换，而不是重新生成

验证失败后，系统首先要分类。证据不足时可检索或请求澄清；证据冲突时需要保留冲突并寻求权威来源；参数或 schema 问题可修改候选后重试；瞬态网络错误可带退避地重试；权限拒绝应停止或走审批；不可逆副作用的部分失败应补偿或人工处置。每一类都对应不同状态转移和不同可接受重试次数。把所有失败交回给同一个模型“再想一次”，会掩盖错误类型并放大循环。

模型自评在这里有一个有限但有用的位置：它可标记“我未能找到有效的合同附件”“这两个来源相互冲突”，帮助守护器发现潜在缺口；但它不能单独把任务标为成功。自评的可信度应通过历史 outcome 校准，且在分布变化、复杂高风险任务或证据不可见时降低权重。系统真正信任的是外部可验证进展，而不是流畅度、长度或主观自信。

## 7.3 停止策略：既不粗暴截断，也不把探索当作完成

停止策略至少同时使用六类信号：已验证的成功谓词；无进展；状态或动作的循环/振荡；继续计算的边际价值不足；不可恢复阻塞；以及费用、时间、并发、写操作等硬熔断。硬上限不可删，因为它限制失控的 blast radius；但也不应单独用“第 20 步必停”判断任务失败。一个正在等待已提交的异步制裁筛查的任务，可能只需转入 `WAIT`；一个连续三次读取相同版本合同且没有新证据的任务，才更像需要重规划或交接。

无进展检测不能只比字符串。可计算未完成验收项数量、关键证据覆盖、世界状态 diff、动作语义签名、错误簇和计划关键路径。对于调研 Agent，连续检索不同网页但都没有增加可引用的独立证据，可能仍然是无进展；对于等待外部系统的 Agent，世界版本尚未变化则是合法等待，前提是有回调、轮询策略和 deadline。阈值应由任务后果与历史分布校准，不能从网上复制“连续三次”作为通用真理。

## 7.4 一个停止与交接的执行情境

假设 Agent 已完成合同和政策核验，但制裁筛查因服务商故障持续 `unknown`。若模型为了写出完整报告而凭公开搜索推断“未发现风险”，就是幻觉；若 runtime 因没有最终结果不断重试，则是循环。正确路径是：记录已验证的两类证据，保留制裁筛查 job 的相关 ID，达到等待窗口后生成一个 `handoff` 包；该包写明目标、已完成验收项、未完成项、最近观察、风险和推荐的人类动作。任务终态是 `BLOCKED` 或 `HANDOFF`，不是伪成功，也不是没有解释的失败。

若后来回调到达，运行时必须先检查 run 是否仍在可恢复窗口、请求主体是否仍有权限、合同和政策前提是否仍有效；否则不能直接把旧结果拼回报告。这个检查说明“异步等待”不是循环的例外，而是状态机中的一等路径。

## 7.5 指标和边界

应报告验证覆盖率、false-success 与 false-failure、模型自评与外部 verdict 的校准误差、无进展循环率、STOP/ASK_HUMAN 的 precision/recall、预算熔断前得到可行动终态的比例以及人工交接后的解决率。安全高后果不变量通常需要发布测试集内零违规；它不能被一个平均成功率抵消。评测既应检查最终交付，也应检查过程是否遵守工具、权限和证据约束，因此需要分开任务定义、试跑、轨迹、评分器与环境结果。[R10]({{ '/references/#r10' | relative_url }})

验证也有成本。对低价值草稿不必让每一句话都经过多模型陪审；应按主张后果、可逆性和来源可靠性分层。对无法形式化的创意任务，可以让用户验收成为完成谓词，但仍要保留预算、权限、数据边界与终态。第八章进一步讨论由人和多个 Agent 共同承担这些不确定点时，如何避免把协作变成新的失控来源。
