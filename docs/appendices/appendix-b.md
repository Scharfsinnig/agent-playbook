## B.2 A0—A5 自治等级的统一口径

自治等级描述的是“系统被允许产生什么外部效果以及怎样放行”，不是模型能力分数。同一个 Agent 可以对查询或草稿是 A1、对白名单内可逆自动写入是 A3、对逐次确认的退款是 A2、对合同签署是 A0；评审必须按动作类别分别填写，不能只给整个产品贴一个等级。升级等级也不等于更先进，只有在验证、恢复和责任证据足以覆盖新增后果时才有意义。

- **A0：不授权 Agent 参与运行时行动。** 业务由人或确定性系统完成；模型最多用于隔离环境中的分析、评测或候选方案研究，其输出不会自动进入业务决策或系统记录。停止方式是禁用该能力，任何上线都要重新立项评审。
- **A1：只读辅助与草稿。** Agent 只能读取已授权数据、解释、分类、检索、生成建议或草稿；不能改变权威业务状态、对外发送或代表主体作出承诺。交付必须标明证据和不确定性，由人决定是否采用；发现越权、证据冲突或预算耗尽时转人工或停止。
- **A2：逐次确认的受监督行动。** Agent 可以准备完整的结构化 diff、交易预览或待提交动作，也可在沙箱和草稿域内写入；每次真实业务写入都要由有权主体看到对象、参数、价格/影响和有效期后确认，审批令牌必须绑定该版本与参数。服务端仍独立鉴权、幂等去重、写后验证；确认失效、对象变化或结果未知时不得自动重放。
- **A3：白名单内的有界自动执行。** Agent 可在预先批准的租户、对象、额度、时段和工具集合内，自动执行低至中等后果、可逆且可验证的写动作；超出信封的动作降为 A2 或 A1。最低要求包括独立策略门、目标系统原子幂等、后置条件验证、最大暴露、在线监测、可补偿路径与随时人工接管。
- **A4：任务信封内的多步委托自治。** Agent 可在一个已批准任务契约内跨多个步骤或系统自行规划和恢复，并执行事先列明的、可对账和可补偿的业务动作，不要求每一步都人工确认。它必须使用耐久状态、提交时重验权限、saga/补偿、独立 verifier、异常 on-call、K2/K3 与自动缩权；不可逆或依法必须由人承担的决定仍需新审批，不能因整体等级较高而被自动放行。
- **A5：高保证环境中的持续委托自治。** Agent 可在形式化、版本化且持续监测的使命信封内处理长期任务、选择合格计划并处置常规故障，但无权修改自己的任务契约、权限、政策、奖励、评测器或发布门禁。该等级只适用于有独立监控、隔离故障域、强制回放/对账、经常性停止演练和明确法律责任的窄场景；它不是“无限自治”，一旦证据、环境或控制失效，系统必须自动降到 A3/A2/A1 或停止。

## B.3 活动级 RACI 与值班责任

RACI 中，A（Accountable）是对决议和剩余风险最终负责的人，每项活动只能有一个；R（Responsible）是执行并提交证据的主责，可有协作者但必须指定一个 lead；C（Consulted）在决定前参与；I（Informed）在决定后获知。RACI 不取代安全、隐私、法务或数据 owner 的独立阻断权，也不允许同一人同时实现控制、批准豁免和证明控制有效。下面是默认最小分配；组织可改角色名称，但必须在用例台账中保存唯一 A、lead R、替补、on-call、升级路径和有效期。

- **批准新用例。** A 为业务 owner；lead R 为产品/工程 owner；C 至少包括平台/SRE、安全、隐私/法务、数据 owner 与受影响运营团队；I 包括 on-call、客服/支持和相关供应商管理人员。
- **提升真实写权限或自治等级。** A 为登记的业务风险接受者；lead R 为产品/工程 owner，平台 owner 负责落实 capability 与策略；C 包括目标系统 owner、安全、隐私/法务和财务/风控（如适用）；I 包括 on-call、审计和受影响运营团队。未获得独立策略 owner 的阻断项关闭证据，不得以业务 A 的单独签字绕过。
- **增加数据类别或改变处理地域。** A 为有权作出适用性与处理结论的隐私/法务 owner；lead R 为数据/产品工程 owner；C 包括业务、安全、平台、数据 owner 和供应商管理；I 包括 on-call、审计及需更新告知或合同的团队。业务目的变化还要另行由业务 owner 批准。
- **发布模型、Prompt、工具、策略或索引组合。** A 为登记的服务/发布 owner；lead R 为发布工程或平台 owner；C 包括业务、SRE、安全、隐私/法务和评测 owner；I 包括 on-call、客服/支持与受影响租户负责人。release manifest、canary 阈值和一致回滚包缺一不可。
- **批准豁免。** A 为独立于实施团队、且有相应额度和风险授权的风险接受者；lead R 为缺口控制 owner；C 包括业务、安全、隐私/法务、平台/SRE和受影响系统 owner；I 包括 on-call 与审计。豁免必须有范围、补偿控制、最大暴露、到期日和自动撤销条件，不能覆盖法律禁止或基本停止能力缺失。
- **执行 K2 策略阻断或 K3 凭证吊销。** A 为当班 incident commander；lead R 分别由策略平台 on-call 或身份/安全 on-call 承担；C 包括服务 owner、安全、业务及隐私/法务（按事故性质）；I 为其他响应者和受影响运营团队。权限与 break-glass 路径必须预先配置，不能在事故发生后等待 Agent 或供应商批准。
- **执行发布回滚。** 活跃事故中 A 为 incident commander，计划性回滚中 A 为登记的发布 owner；lead R 为平台/SRE on-call；C 包括产品工程、业务、安全和数据 owner；I 包括客服/支持与受影响租户。回滚必须覆盖相互兼容的模型、Prompt、工具、策略与索引，而不是只换模型版本。
- **事故披露与外部通知。** A 为组织正式授权的法务/合规负责人或高管；lead R 为事件沟通负责人，incident commander 负责提供已核验事实包；C 包括安全、隐私、业务、服务 owner 和公共关系；I 按法律、合同和影响范围包括监管方、客户或受影响个人。任何 Agent 只能整理证据和草拟通知，不能自行判断披露义务或发送正式声明。

## B.4 P0 硬门禁

### 任务与责任

- [ ] 任务契约明确目的、主体、资源范围、禁止动作、完成谓词、证据、预算和终态。
- [ ] “完成”由环境状态、测试、回执或人工签字验证，不由模型自报。
- [ ] 每类动作按影响、可逆性和敏感度定义自治等级；高后果动作有人工责任。
- [ ] 业务、安全、隐私/法务、平台、on-call 与人工审批责任到人。

### 身份、权限与行动

- [ ] 敏感工具调用绑定用户/工作负载身份、租户、用途和短时最小权限。
- [ ] System Prompt 不承担访问控制；策略在模型外的工具边界强制执行。
- [ ] 参数使用 typed API/schema/枚举/服务端租户过滤，不直接拼 shell、SQL 或 URL。
- [ ] 写操作有幂等键、绑定参数哈希的审批、并发控制、写后验证和必要补偿。
- [ ] 不可逆动作前已完成全部验证，并将 blast radius 限到最小。

### 数据、RAG 与记忆

- [ ] 查询时强制 ACL/tenant filter；来源、版本、有效期和冲突可追溯。
- [ ] 用户、网页、邮件、检索、工具返回和 Agent 消息均按不可信输入处理。
- [ ] 长期记忆写入经过隔离与验证；可过期、更正、删除、回滚和审计。
- [ ] Prompt、trace、缓存、向量库和训练数据不暴露凭证或越用途敏感数据。
- [ ] 跨租户检索、缓存、trace、沙箱和模型 batch 的负向测试全部通过。

### 安全与供应链

- [ ] threat model 覆盖 prompt injection、外泄、过度代理、代码执行、投毒、无界消耗。
- [ ] 高价值 sink 前有确定性策略、DLP/egress、权限和审批；输入检测不是唯一防线。
- [ ] 模型、adapter、Prompt、MCP/工具、依赖、索引和评测资产有来源、版本与撤销开关。
- [ ] 代码/浏览/文件转换运行在临时最小权限沙箱，无法访问宿主 metadata/secret/任意网络。
- [ ] 生产 Agent 无权同时修改训练数据、奖励、评测、策略和发布制品。

### 评测、发布与运行

- [ ] 结果、单步、轨迹、安全、鲁棒、可靠性、成本和业务指标分别评测。
- [ ] P0 用例在固定集、时间外盲测和红队中零越权/外泄/错误高后果动作。
- [ ] 确定性评分优先；LLM judge 已在人标保留集校准，未作为安全放行唯一依据。
- [ ] 版本化 release manifest 覆盖模型、Prompt、工作流、工具、策略、索引和依赖。
- [ ] shadow→canary→分批发布有阈值、最大暴露、自动回退和人工停止。
- [ ] feature deny、policy deny、credential revoke、release rollback、global kill 已演练。
- [ ] 高风险 run 可从业务请求追到身份、策略、版本、审批、工具、副作用和回退。

### 合规与退出

- [ ] 已按用途、角色、地域、受影响人和数据类别完成适用性评估；不是按“用了 Agent”笼统分类。
- [ ] 生成内容披露/标识、数据保留/删除、供应商条款和通知义务有明确结论。
- [ ] 若面向中国境内公众提供生成式 AI 服务，已判断暂行办法、安全评估/算法备案；显式标识、元数据隐式标识、导出保持和传播核验分别按角色与触发条件落实。若采用《标识办法》第九条“不含显式标识”的例外，协议已明确用户责任，并依法留存提供对象信息等相关日志不少于六个月；该要求未被泛化为普通内部 Agent 的统一日志规则。[R59]({{ '/references/#r59' | relative_url }})
- [ ] 若涉及欧盟，已按截至 2026-08-19 的修订时间线逐用例核对：GPAI 模型提供者义务原则上自 2025-08-02 适用，但此前已投放的模型过渡至 2027-08-02；2026-08-02 前投放的生成合成内容系统，其 Article 50(2) 标记义务过渡至 2026-12-02；Annex III 与 Annex I 高风险系统的实质规则分别自 2027-12-02 与 2028-08-02 适用；Omnibus 新增禁止实践自 2026-12-02 适用。所有日期仍须结合角色、条款、例外和当前合并文本判断。[R58]({{ '/references/#r58' | relative_url }})
- [ ] 豁免有风险接受者、补偿控制、到期日和自动复审。
- [ ] 有供应商退出和系统下线计划：停流量、撤凭证、对账、数据处置和替代流程。

## B.5 P1 生产能力

### 循环与状态

- [ ] 状态机区分接收、上下文、计划、授权、执行、观察、验证、等待、补偿和终态。
- [ ] 停止综合成功、无进展、重复/振荡、价值早停、阻塞和硬预算。
- [ ] 崩溃恢复、重复投递、超时、取消、外部等待和运行中版本迁移有测试。
- [ ] 计划含前提、版本和失效条件；恢复时重验权限、新鲜度和 deadline。

### 工具与多 Agent

- [ ] 工具声明前置/后置、effect、风险、权限、费用、超时、幂等、补偿和输出信任。
- [ ] 错误区分 transient/permanent/ambiguous；重试有退避、熔断和状态查询。
- [ ] 多 Agent 确有并行/互补增益；角色契约包含目标、验收、scope、预算和截止。
- [ ] 子 Agent 权限不超父任务；消息有身份、来源、schema 和 parent trace。
- [ ] 共享状态有字段 owner、版本和冲突策略；有死锁、孤儿和循环委托检测。

### 可观测、SLO 与经济

- [ ] 根 trace 关联模型/Prompt/工具/索引/策略版本、Token、成本、审批和业务终态；若采用演进中的 OpenTelemetry GenAI 约定，release manifest 固定 tag/commit 与 `schema_url`，升级通过旧/新映射或双写、查询兼容和历史回放验收。
- [ ] SLO 以安全有效终态为中心，并按用例、风险、租户、工具和版本切片。
- [ ] 漂移同时监测输入、动作、结果、成本和制品变化，不只看模型输出均值。
- [ ] 计算 cost per safe accepted task，含工具、人审、返工、观测和失败期望损失。
- [ ] 单请求/租户/工具/周期有 Token、步骤、时间、费用、并发和递归预算。
- [ ] 模型/工具故障有受评测降级、队列/缓存、人工接管和灾备 RPO/RTO。

### 数据飞轮与模型适配

- [ ] 失败已归因到契约、上下文、记忆、规划、工具、状态、模型或治理层。
- [ ] 已证明微调/RL 相对 Prompt、RAG、工具修复和 verifier 有必要的增量。
- [ ] 轨迹进入学习前确认用途、适用处理合法基础、告知/同意（如适用）、合同/地域限制，并完成脱敏、结果验证、归因证据、污染和代表性检查。
- [ ] train/dev/time-holdout/red-team 严格分离；自生成数据有来源标记，并按独立外部锚点、时间外测试、真实/专家数据覆盖和安全回归校准抽样权重与比例，不使用跨场景固定阈值。
- [ ] 新模型通过目标能力、旧能力、安全、经济和校准/稳定性五组回归。
- [ ] 学习策略只在已批准安全动作集合内探索，且有最大 regret、费用和到期日。

## B.7 事故复盘映射

对每起事故强制回答：

1. 首个错误决策/状态转移发生在哪个 span？
2. 对应完整地图中的哪个 Q001–Q150？
3. 是控制未设计、未实现、未执行，还是未观测？
4. 为什么 verifier、策略、审批、告警或人没有更早发现？
5. 哪个回归/红队案例可稳定复现？
6. 如何缩小权限、数据、流量、租户和时间的 blast radius？
7. 修复是否改变模型、Prompt、工作流、工具、策略、索引或数据；如何回滚？
8. 是否需要更新任务契约、培训、供应商条款、披露或法规证据？

完整解释见正文各章；问题导航见附录 A。
