# 第 10 章　Workflow、单 Agent 与多 Agent 的选择边界

## 10.1 选择问题不是“谁更先进”

团队常把固定流程包装成 Agent，或者把真正开放的异常处理硬塞进 Workflow。两者都会带来错误成本。正确选择取决于路径可预知性、环境反馈质量、动作后果、任务时长、可分解性和验证能力。路径稳定、字段明确且后果高时，应由确定性 Workflow 主导，模型只承担分类、抽取或草拟；路径未知但每一步可观察、动作可逆且有验证器时，单 Agent 才有价值；只有子任务可独立验收、能力或证据确实互补、并行收益超过协调成本时，才应引入多 Agent。

供应商调研本身可采用“Workflow 外壳 + 局部 Agent”混合形态：身份、合同版本、制裁筛查、审批创建和最终归档是确定性节点；模型负责从条款中提出风险 claim、为缺失证据设计检索策略、综合为带引用的草稿。若要独立复核公开风险和合同解释，可以在这两个可交换子任务上并行 Agent；最终准入状态仍由确定性规则和人类负责人决定。这种组合比“全程自由 Agent”更容易测试，也比完全规则化更能处理开放材料。

## 10.2 一个可执行的选择过程

第一步把任务的动作按可逆性与后果切分。若某一步不可逆或强监管，先问是否可以改为建议、草稿或审批式操作；若不可以，优先 Workflow 与人类责任。第二步判断是否有外部反馈：代码 Agent 能运行测试、研究 Agent 能验证引用、业务 Agent 能读取权威状态，因而可形成闭环；没有反馈的任务不宜扩大自治。第三步估计路径稳定性：稳定路径编译成 DAG，开放节点给 Agent；不要让模型每次重新发现已知业务流程。第四步评估可分解性和协调成本，再决定是否 fan-out。

可以把决策写成简短的运行时规则，而不是一张宣传图：当 `predictability` 高且 `harm` 高，选择 Workflow；当 `feedback` 足够、`harm` 有界且存在未知路径，选择单 Agent；当独立子任务的边际价值大于通信、合并、权限和等待成本，选择带聚合契约的多 Agent；任何情况下，只要 `verifiability` 或接管能力接近零，就缩小到建议或人工处理。这里的变量需要以业务证据而非主观印象估计。

## 10.3 三种形态的工程差异

Workflow 的优势是控制流可预先测试、恢复语义明确、成本和责任易预测；缺点是面对未预见异常时需要开发变更。单 Agent 的优势是能在允许的动作集合内针对新情况选择路径；代价是更高的状态、验证、预算和观测要求。多 Agent 的优势不是“角色扮演”，而是隔离权限、并行独立工作、产生去相关证据或将大型任务拆成故障域；其代价包括通信、合并、死锁、共享状态冲突和信用分配。

因此，形态间不是升级阶梯。一个可靠的系统可能在相同产品中同时使用三种形态：每天的供应商资料同步是 Workflow；一份新合同的条款摘要是单 Agent 受控节点；高价值或争议案件才调用合同、风险、法务三个专家产物并由聚合器准备人审。每种形态共享同一套契约、工具门、状态事件和验证指标，区别只在控制路径由代码还是模型决定，以及是否需要多个相互隔离的工作单元。

## 10.4 选择错误时会怎样表现

把 Workflow 误当 Agent，常见症状是团队无法处理一条新异常就不断添加分支，最后形成难维护的 if-else 网络；其补救是找出真正开放的语义节点，给它受约束的模型提案和验证器。把 Agent 误用于稳定流程，症状是同样的输入得到不同路径、成本波动、难以审计；应把稳定步骤下沉到代码。过早多 Agent 的症状是消息量与 token 上升、答案相关性很高、合并冲突和等待环增多而成功率没有提升；应回退为单 Agent 或 DAG。

“模型更强”不能单独改变这个选择。更强的模型或许扩大了可安全处理的语义不确定范围，却没有让权限、事务、业务后果和人类责任消失。相反，模型能力提升会提高系统发现更复杂动作的概率，更需要严格的 allowlist、预算和验证。

## 10.5 选择后的验收与案例结论

上线前应以可比较基线验证选择是否合理：Workflow 基线的完成率、时延和人工量；单 Agent 相对该基线在未知路径中的净增益；多 Agent 相对强单 Agent 的增量成功、成本、关键路径、错误相关性和人审负担。对于每个高后果动作，还要验证同一套拒绝、取消、恢复、超时、并发冲突和注入测试在所选形态下都成立。

供应商案例的最终设计因而不是“一个会自动判断准入的超级 Agent”。它是一个由任务契约启动的受控 run：确定性 Workflow 负责登记、身份、版本、审批、归档与不可逆边界；单 Agent 在授权上下文中编排开放检索与文本综合；必要时多个专家 Agent 产出独立、可验证的 artifact；工具网关实施权限、幂等、等待和事务；验证器与人类负责人决定是否完成、交接或停止。这一边界为后续章节讨论模型分工、RAG、训练与持续进化提供了前提：任何学习算法都只能优化闭环中的局部选择，不能取代任务契约、外部验证和治理责任。
